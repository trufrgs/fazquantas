# Fodinha — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fodinha com baralho espanhol, completa e testada, jogável local contra bots e online (servidor
Node na rede local), pronta para deploy e empacotamento Android/iOS.

**Architecture:** monorepo pnpm com um motor de regras puro e determinístico (`@fodinha/engine`)
compartilhado por um webapp React/Vite (modo local roda o `GameHost` no navegador) e um servidor
socket.io (modo online roda o mesmo `GameHost` por sala). Capacitor empacota o build web.

**Tech Stack:** TypeScript 6.0, Vite 8, React 19, Tailwind 4, Motion 13, zustand 5, howler, DiceBear,
canvas-confetti, lucide-react, socket.io 4.8, zod 4, Vitest 5, Playwright, Capacitor 8.

**Spec:** `docs/superpowers/specs/2026-09-27-fodinha-design.md`

**Execução escolhida:** Native (implementação nesta sessão, com revisor independente no fim), porque o
usuário pediu autonomia e as tarefas dependem fortemente das interfaces do engine.

## Global Constraints

- UI 100% em pt-BR com acentuação correta; código e commits em inglês.
- Node ≥ 22; pnpm workspaces; TypeScript `~6.0` (typescript-eslint não suporta 7).
- Todo comando de teste com `--maxWorkers=3` (limite de RAM da máquina).
- Engine sem dependências de runtime e sem acesso a `Math.random`/`Date` (tudo injetado).
- Nenhuma informação oculta sai do servidor: cada cliente recebe só a própria visão.
- Assets só com licença livre e atribuição registrada em `CREDITS.md` e na tela de créditos.
- Layout funciona de 360×640 (retrato) até desktop, sem scroll horizontal.
- Sem chat livre; sem login; apelido e ajustes em `localStorage`.

## Review Focus

1. **Recarregar/fechar o app no meio da partida** — local: a partida deve voltar exatamente onde
   parou ("Continuar partida"); online: reconectar no mesmo assento com a visão completa. → testes na
   Task 6 (serialização do host) e Task 8 (reconexão por token).
2. **Toque duplo / ação fora da vez / atraso de rede** — ação repetida ou fora de hora é rejeitada sem
   dessincronizar; a UI trava a entrada até a próxima visão. → testes na Task 3 (erros do reducer) e
   Task 8 (ação duplicada via socket).
3. **Tela pequena com 8 jogadores e mão grande** — 360×640 com 8 jogadores e 10+ cartas continua
   legível e sem sobreposição que impeça tocar. → screenshot obrigatório na Task 17.
4. **Anfitrião sai / todos os humanos saem** — a sala transfere o anfitrião ou é limpa; ninguém fica
   preso numa sala morta. → testes na Task 8.
5. **Áudio bloqueado no mobile e som desligado** — nada quebra antes do primeiro toque; mudo respeita
   o ajuste. → teste unitário do módulo de som na Task 12 (sem erro sem contexto de áudio).

### Task 2: Cartas, PRNG e hierarquia

**Interfaces (Produces):**
```ts
type Suit = 'O' | 'C' | 'E' | 'P'            // ouros, copas, espadas, paus
type Rank = 1|2|3|4|5|6|7|10|11|12
interface Card { id: CardId; suit: Suit; rank: Rank }   // CardId = `${Suit}${Rank}` ex. 'E1'
const SUITS: Suit[]; const RANKS: Rank[]; function fullDeck(): Card[]; function card(id): Card
function cardName(card): string               // "Ás de espadas", "Sete de ouros", "Rei de copas"
function createRng(seed: number): Rng          // { next(): number in [0,1); int(n); state }
function shuffle<T>(arr: T[], rng: Rng): T[]
type HierarchyMode = 'gaucha' | 'paulista'
interface StrengthCtx { mode: HierarchyMode; vira: Card | null }
function manilhaRank(vira: Card): Rank
function strength(card: Card, ctx: StrengthCtx): number   // maior = mais forte; empates = mesmo número
function isManilha(card: Card, ctx: StrengthCtx): boolean
function specialName(card: Card, ctx: StrengthCtx): string | null  // Espadão, Bastião, Zap, Pica-fumo…
function sortByStrength(cards: Card[], ctx): Card[]      // fraca → forte
```
- [ ] Testes: 40 cartas únicas; ordem gaúcha completa (E1>P1>E7>O7>3>2>C1=O1>12>11>10>C7=P7>6>5>4);
  paulista: vira 7 → manilha 10; vira 3 → manilha 4; vira 12 → manilha 1; manilhas P>C>E>O acima de
  tudo; mesma semente ⇒ mesmo embaralhamento; nomes pt-BR.
- [ ] Implementar, rodar, commit `feat(engine): cards, rng and hierarchy`.

### Task 3: Regras e reducer do jogo

**Interfaces (Produces):**
```ts
interface Rules { hierarchy: HierarchyMode; startingLives: number; penalty: 'difference'|'fixed';
  tieRule: 'cancel'|'first'; blindOneCardRound: boolean; dealerRestriction: boolean;
  progression: 'upDown'|'up'; maxCards: number | null }
const DEFAULT_RULES: Rules; const PRESETS: Record<'tradicional'|'paulista'|'rapida', Rules>
function normalizeRules(partial: Partial<Rules>): Rules
interface PlayerInfo { id: string; name: string }
function createGame(cfg: { players: PlayerInfo[]; rules: Rules; seed: number; firstDealer?: number }): GameState
type Action = { type:'bid'; playerId; value:number } | { type:'play'; playerId; cardId } | { type:'continue' }
type ApplyResult = { ok: true; state: GameState } | { ok: false; error: GameError }
function applyAction(state: GameState, action: Action): ApplyResult
function legalBids(state, playerId): number[]; function legalCards(state, playerId): CardId[]
function resolveTrick(plays: {playerId; card}[], ctx, tieRule): { winnerId: string|null; cancelled: string[] }
function maxCardsFor(alive: number, rules): number
function currentActor(state): { playerId: string; kind: 'bid'|'play' } | null
```
`GameState` guarda `rules`, `players[] {id,name,lives,eliminatedRound|null}` na ordem do jogo,
`phase`, `roundNumber`, `dealerIndex`, `cardsThisRound`, `direction`, `round` (mãos, vira, apostas,
ordem, vaza atual, vazas feitas, `completedTricks`), `lastTrick`, `history[]`, `rngState`, `result`.
- [ ] Testes (antes da implementação): criação distribui 1 carta; ordem de aposta começa após o
  carteador; pé não pode fechar (e pode quando a regra está desligada); aposta inválida/fora da vez
  retorna erro sem mudar estado; jogar carta que não tem → erro; vaza resolve com anulação (3,3,2 ⇒
  quem jogou o 2; 3,3 ⇒ ninguém, quem começou recomeça) e com "primeira vence"; vencedor começa a
  próxima; fim da rodada aplica diferença e fixa; progressão 1→máx→1→2 e "só sobe"; máximo com vira usa
  39; eliminação; carteador pula eliminados; eliminação simultânea decide por mais vidas e empate;
  `continue` só vale em `trickEnd`/`roundEnd`; nada acontece após `gameOver`.
- [ ] Implementar `rules.ts`, `types.ts`, `game.ts`; commit `feat(engine): game reducer`.

### Task 6: GameHost
